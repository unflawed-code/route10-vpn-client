## 🚀 Summary

Release v1.4.0 makes the kill switch enforce the tunnel, not just the routes: every routed client may now leave only through its own VPN interface, so a dropped tunnel blocks that client instead of letting it fall back to the WAN address.

## ✨ Highlights

- **Feature**: Each interface gets a `<interface>_killswitch` chain that rejects egress through anything but its tunnel device, applied to every target whether it is listed as an address, a subnet or a MAC address.
- **Improvement**: The rules are installed before the routing table is rebuilt and the chain and its jump are recreated if they are missing, so a missing tunnel, an absent route and a freshly flushed firewall all fail closed with the same rule set.
- **Improvement**: Traffic to the interface's own LAN bridge is exempted from the reject, so casting, printing and other on-LAN services keep working, and LAN-to-LAN forwarding is untouched.
- **Fix**: A comma-separated target list now produces one rule per target instead of a single malformed rule that matched nothing.
- **Fix**: Roaming clients have the old pinned rule removed before it is re-added at their new address, and interfaces whose clients span several bridges keep the LAN exemption ahead of the reject rules.

## ⬆️ Upgrade Notes

- Existing interfaces keep the hotplug script they were installed with, so re-run the interface setup for each tunnel (`wg.sh <iface> -c <conf> -t <targets>`) after updating. `wg.sh reapply` replays the installed script and does not add the new rules by itself.
- No configuration, database or target changes are required, and interfaces that are not routed through a tunnel are unaffected.
